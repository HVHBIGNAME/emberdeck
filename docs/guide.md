# Installation & operations

For quick HTTPS, Cloudflare connector tokens, managed Caddy, existing reverse proxies and the web command generator, see [installation profiles](installation-profiles.md).

## Native installation

The release executable includes the web interface, API, CLI, node agent, and SFTP server. Docker is required on Minecraft nodes and for the managed Caddy profile; a panel using private access or a tunnel does not require it. SQLite is embedded.

```bash
curl -fsSL https://raw.githubusercontent.com/HVHBIGNAME/emberdeck/main/install.sh | sudo bash
```

The installer supports Ubuntu / Debian with systemd. For another Linux distribution, install Docker and CA certificates with your package manager, then use the native binary and the service definitions generated by the installer. Release Linux binaries use musl to avoid depending on a specific glibc version.

| Location | Purpose |
| --- | --- |
| `/usr/local/bin/emberdeck` | Native executable with embedded UI |
| `/etc/emberdeck/panel.toml` | Panel settings and node credential |
| `/etc/emberdeck/agent.toml` | Agent settings and management-token hash |
| `/etc/emberdeck/owner-token` | Initial owner token; root-readable |
| `/var/lib/emberdeck/panel` | Panel SQLite database |
| `/var/lib/emberdeck/agent` | Agent database, SSH host key, diagnosis workspaces |
| `/var/lib/emberdeck/servers/<id>` | Minecraft data |
| `/var/lib/emberdeck/backups/<id>` | Local backup archives |

The panel runs as the `emberdeck` system user. The agent needs Docker-socket access and permission to manage server files. It runs as root; its management endpoint is privileged.

```bash
sudo systemctl status emberdeck-panel emberdeck-agent
sudo journalctl -u emberdeck-panel -u emberdeck-agent -f
```

Existing configurations and tokens are kept on upgrades. The previous executable is retained at `/usr/local/bin/emberdeck.previous`.

## Custom ports

Environment variables apply to a **fresh** installation:

```bash
curl -fsSL https://raw.githubusercontent.com/HVHBIGNAME/emberdeck/main/install.sh -o install.sh
sudo env \
  EMBER_PANEL_LISTEN=127.0.0.1:18080 \
  EMBER_AGENT_LISTEN=127.0.0.1:18081 \
  EMBER_SFTP_LISTEN=0.0.0.0:22022 \
  EMBER_PUBLIC_URL=http://localhost:18080 \
  EMBER_PUBLIC_HOST=play.example.com \
  bash install.sh
```

Other installer options: `EMBER_VERSION=v0.2.0`, `EMBER_MODE=panel|agent|all`, and `EMBER_BINARY=/absolute/path/to/emberdeck` for a locally built release. Access profiles also have command-line flags; run `bash install.sh --help` for the complete list.

For an existing installation, update the TOML configuration and restart the affected service. Initial node metadata is persisted in the panel database; manage additional nodes in **Nodes**. Use distinct panel, agent, SFTP and game ports.

## Private access and HTTPS

For a private workspace, keep the default loopback listeners and use a tunnel:

```bash
ssh -L 8080:127.0.0.1:8080 root@your-server
```

For a public panel, place a TLS reverse proxy in front of `127.0.0.1:8080`. Example Caddy configuration:

```caddyfile
panel.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Set `public_url = "https://panel.example.com"` in `panel.toml`, then restart the panel. HTTPS enables the `Secure` cookie flag. Preserve the incoming `Host` header so same-origin checks work. The installer doesn't change your existing reverse proxy or firewall.

## More than one node

1. Install the binary on another Linux host using `EMBER_MODE=agent`.
2. Put the loopback agent endpoint behind authenticated HTTPS transport at your reverse proxy, or reach it through a private SSH tunnel. The application still requires its node token.
3. Retrieve the agent token on that host. It is generated into the `agent_token` field of `/etc/emberdeck/panel.toml`; `agent.toml` stores only its hash.
4. In the main panel, choose **Nodes → Connect node**. Supply the endpoint, management token, public game hostname and SFTP port.

Example agent proxy:

```caddyfile
node.example.com {
    reverse_proxy 127.0.0.1:8081
}
```

Remote node registration requires HTTPS. HTTP is accepted only for loopback addresses, useful for SSH tunnels. Use a publicly trusted certificate or install your private CA in the panel host's trust store.

## Files and SFTP

The Files tab supports browsing, text editing, renaming, empty-folder deletion, uploads and downloads. Text saves include an expected SHA-256 hash to detect concurrent changes. Web transfers are limited to **32 MiB**; use SFTP for larger files.

Choose **Files → SFTP → Generate access**. Each credential:

- is scoped to exactly one server;
- expires after one hour by default (API: 1 minute–24 hours);
- is read-only or read/write;
- permits SFTP only, not a shell or SSH port forwarding.

Use the supplied server ID as the username and the generated token as the password. Verify the persistent SSH host-key fingerprint with your node administrator on first connection. Symbolic / hard link creation and remote chmod/chown are not exposed. Some clients may report that preserving upload timestamps is unsupported.

The SFTP port must be reachable through your host and provider network rules. You can also forward it through an existing administrative SSH connection:

```bash
ssh -L 2022:127.0.0.1:2022 root@your-server
```

Then connect your SFTP client to `127.0.0.1:2022` with the generated server-scoped credentials. Substitute your configured SFTP port when using custom ports.

Revoking an API token invalidates its browser sessions immediately. Already-issued SFTP leases have an independent lifetime. Stop the SFTP service or remove the relevant credential from the agent database if immediate lease invalidation is essential.

## Backups to Google Drive or S3

Local backups work without additional software. Cloud copies use an optional **rclone** executable on the node:

```bash
sudo apt-get install rclone
sudo rclone config --config /var/lib/emberdeck/agent/rclone.conf
sudo chmod 600 /var/lib/emberdeck/agent/rclone.conf
```

Create a Google Drive remote named `gdrive` using rclone's OAuth flow. In `agent.toml`, set these **top-level** fields (replace the existing `backup_remotes` entry):

```toml
rclone_config = "/var/lib/emberdeck/agent/rclone.conf"
backup_remotes = { drive = "gdrive:Emberdeck" }
```

Restart `emberdeck-agent`. The **drive** destination appears in Backups and automation forms. Use another configured rclone remote for S3, WebDAV, or other supported storage.

Keep rclone's OAuth configuration in the writable agent data directory so token refresh can update it. The systemd agent intentionally cannot write under `/etc`.

Archives are created locally first. A failed upload preserves the local copy and records `remote_state: failed`. Restore currently uses a local archive, verifies its SHA-256, makes a rollback backup, extracts only regular files/directories inside a staging root, and replaces the stopped server's data. Remote-only restore and automatic retention pruning are not implemented yet.

## Automations

Supported triggers: `cron`, `interval`, `player_join`, `player_leave`, and `empty` (transition from players present to zero). Actions: Minecraft command, start/stop/restart, or backup.

- Cron uses five fields and an IANA timezone. In this release, weekday numbers follow the Rust cron parser: **1=Sunday … 7=Saturday**; named weekdays are also supported.
- Intervals must be at least 30 seconds.
- A player filter is case-insensitive and matches one exact Minecraft username.
- `{player}` is replaced only with a validated player name.
- “Only when empty” requires a successful player observation. An unavailable server is not assumed empty.
- The scheduler rechecks the creator token's permissions. Expired/revoked owner tokens disable their tasks.

Observations are polled approximately every 10 seconds, with additional latency on busy nodes. Very short join/leave sessions can be missed. Missed schedules are coalesced, not replayed repeatedly after downtime. Run **one panel process per database**.

## Ember assistant

Configure an OpenAI-compatible chat-completions provider in `panel.toml`:

```toml
ai_base_url = "https://api.openai.com/v1"
ai_model = "gpt-4.1-mini"
ai_api_key = "your-provider-key"
```

`EMBER_AI_API_KEY` may supply the key instead. Configure it with a private systemd environment file, then restart the panel.

Only an explicit assistant request sends data to the provider: the selected server configuration, current observation, and redacted recent logs. Redaction is best-effort; inspect your plugins' logging behavior. Local pattern analysis and static JAR reviews do not require AI. The assistant can search and propose installations / commands; applying a proposal uses the normal permission-checked API after user confirmation.

## Isolated diagnosis

Stop the original server and open **Diagnostics → Start isolated diagnosis**. An exact error-text signature is optional. Without one, the predicate checks failed startup.

The agent copies the server, verifies that the full set fails and the empty add-on set boots, groups known hard dependencies, minimizes a failing set, and tests its complement. Trials are time- and count-bounded. They publish no game port. Trial containers retain internet access because core installers may need it.

“Apply a verified fix” additionally requires package and backup write permissions. It only runs after a healthy complementary trial and unchanged source JAR hashes. It creates a backup and renames suspects to `.jar.disabled`. Dependency interactions may produce a group rather than a single culprit. Timeout or missing-dependency results are inconclusive. Runtime-only faults need a separate reproduction.

## Windows

The native executable can run `panel`, `demo`, `keygen`, and `cli` on Windows. Use a Linux agent for actual game containers. Build from source or download a Windows artifact when available in Releases. The systemd installer and node agent are Linux-specific.
